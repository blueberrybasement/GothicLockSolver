Puzzle guide

How to model a Gothic plate lock before pressing Solve

Lock Solver Gothic is built for puzzles where several sliding or rotating plates react to one move. The solver is useful when the lock is not a simple one-plate-at-a-time mechanism: moving one plate can push another plate in the same direction, pull it in the opposite direction, or leave it unchanged.

1. Record the current plate positions

Treat every hole or notch as a numbered position from 1 to 7. Start with the visible state in the game or puzzle, then use the plus and minus controls in the middle panel until each row matches what you see on screen.

2. Set the target position

Many Gothic lock puzzles use the central position as the goal, so position 4 is selected by default. If your puzzle clearly highlights another target hole, change the target before solving.

3. Map plate dependencies

The relation matrix is the important part. A row means the plate you move. A column means the plate that reacts. Use + when the reacting plate follows the same direction, - when it moves the opposite way, and none when there is no reaction.

4. Read the shortest sequence

After solving, the result lists the shortest sequence found for the model you entered. Click any step to preview the state after that move and compare it with the actual puzzle before continuing.

Worked example

A practical way to identify relations without guessing

Test one plate at a time

  1. Write down the starting positions of every plate.
  2. Move only plate 1 by one step in the direction you call +.
  3. Compare every other plate with the starting state.
  4. Enter +, -, or none in row 1 of the matrix.
  5. Undo the move if possible, then repeat the same process for the next plate.

When the answer looks wrong

Most wrong answers come from one reversed convention. If the puzzle uses the opposite visual direction, you do not need a new algorithm: either reverse the meaning of + and - in your notes, or use the opposite direction from each listed move.

If the solver reports no solution, re-check whether the target position is correct and whether every dependency was tested from a clean starting state.

Method

How the solver searches for a result

State-based search

The tool represents the lock as a compact state: each plate has a position, and each possible move applies the dependency rules from the matrix. The search checks reachable states until it finds a state where every plate sits on the target position.

Why the first result is short

Moves are explored by distance from the starting state. That means the first valid solution found is the shortest sequence for the model entered into the page. If the real puzzle behaves differently, the matrix needs correction rather than more random moves.
